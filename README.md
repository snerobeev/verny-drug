# Верный Друг · учебный проект для менти по 1С

Учебная конфигурация на 1С:Предприятие. Помимо самой конфигурации здесь выстроен весь путь изменения: исходники в Git, автотесты, конвейер Jenkins и выкладка в рабочую базу.

| Тема | Где смотреть |
|---|---|
| Объекты метаданных: справочники, документы, регистры, перечисления, задачи | `src/` |
| Остатки и движения через регистр накопления, отчёт по остаткам | `AccumulationRegisters/ОстаткиНаСкладах`, `Reports/ОстаткиНаСкладах` |
| Разделение кода на клиент и сервер в тонком клиенте | модули форм в `src/**/Forms` |
| HTTP-сервис и REST API на 1С | `HTTPServices/ShelterAPI` |
| Модульные тесты на YAxUnit: проведение документа, логика задачи | `exts/tests/` |
| Автотесты API на Java: REST Assured, JUnit 5, Allure | `api-tests/` |
| UI-сценарии на Gherkin в Vanessa Automation | `features/` |
| Конвейер CI в Jenkins | `Jenkinsfile`, `tools/` |
| Безопасное обновление рабочей базы: копия, подтверждение, откат | `tools/deploy-prod.sh`, `tools/restore-prod.sh` |
| Работа в Git: ветки, pull request, понятные сообщения коммитов | история репозитория |

## Предметная область

Приют ведёт учёт питомцев, кормов и задач сотрудников.

- **Питомцы:** карточка животного, вид, порода, пол, окрас, статус, вес.
- **Корма:** номенклатура, склады, приход и расход по накладным, остатки на складах.
- **Кормление:** нормы кормления в зависимости от питомца и журнал кормлений.
- **Люди и организации:** приюты, сотрудники, физические лица, контрагенты.
- **Задачи:** задачи пользователей со статусами.

## Конвейер Jenkins

Каждое изменение проходит одни и те же стадии:

1. **Сборка тестовой базы.** Конфигурация загружается из `src/` через `ibcmd`.
2. **Проверка конфигурации.** Расширенная проверка Конфигуратором в пакетном режиме.
3. **Модульные тесты YAxUnit.** Расширение с тестами загружается в тестовую базу, каждый тест идёт в транзакции.
4. **Тесты API.** REST Assured в Docker-контейнере с JDK 21.
5. **Сценарии Vanessa.** UI-тесты в тестовом клиенте (через Xvfb).
6. **Обновление рабочей базы.** Только для `main` и только после подтверждения человеком. Перед обновлением делается копия базы. Если нужна реструктуризация таблиц с данными, конвейер спрашивает подтверждение ещё раз.

Результаты всех тестов собираются в общий отчёт **Allure**.

## Как запустить у себя

**Понадобится:**
- 1С:Предприятие 8.5 (`ibcmd`, Конфигуратор). Режим совместимости конфигурации 8.3.27.
- YAxUnit: `.cfe` из [релизов](https://github.com/bia-technologies/yaxunit/releases), путь задаётся в `YAXUNIT_CFE`.
- Docker (для тестов API) или JDK 21.
- OneScript и vanessa-runner (для сценариев Vanessa).
- Xvfb, если запускаете на сервере без экрана.
- Jenkins с плагином Allure, если нужен конвейер целиком.

**Шаги:**

```bash
git clone https://github.com/snerobeev/verny-drug.git
cd verny-drug

# 1. собрать тестовую базу из исходников
IB_PATH=/путь/к/тестовой/базе tools/build-test-base.sh

# 2. проверить конфигурацию
xvfb-run -a tools/check-config.sh

# 3. прогнать модульные тесты YAxUnit
YAXUNIT_CFE=/путь/к/yaxunit.cfe xvfb-run -a tools/run-unit-tests.sh

# 4. прогнать тесты API (нужен опубликованный HTTP-сервис)
BASE_URL=http://localhost/shelter/hs/api tools/run-api-tests.sh

# 5. прогнать сценарии Vanessa
xvfb-run -a tools/run-tests.sh
```

Пути к платформе и базам задаются переменными окружения (`IBCMD`, `V8`, `IB_PATH` и др.). Значения по умолчанию указаны в начале каждого скрипта в `tools/`.

## Для менти: как работать с проектом

1. Создайте ветку от `main` с понятным названием, например `fix/pet-form-weight`.
2. Внесите изменение и выгрузите конфигурацию в `src/`.
3. Напишите сообщение коммита так, чтобы через месяц было ясно, **что** и **зачем** изменено.
4. Откройте pull request: конвейер сам соберёт базу и прогонит проверки и тесты.
5. Если что-то упало, разберите отчёт Allure, исправьте и запушьте снова.
6. После ревью и зелёного конвейера изменение сливается в `main`.

Хорошая привычка: к каждому исправлению добавлять тест (модульный тест YAxUnit, сценарий Vanessa или тест API), который упал бы без этого исправления.
